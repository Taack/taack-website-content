== 简介

在本节中，我们将学习安全（Security）与约束（Constraints）。首先，我们将学习如何实现这些约束，从而限制用户的输入。接着，我们将通过创建两类用户来深入了解安全机制：管理员（Admins）和借阅者（Borrowers），每类用户都可以访问不同的功能。

管理员可以：

- 在 Author 菜单中添加、删除和重新激活作者。
- 在 Book 菜单中添加图书。
- 在 Book 菜单中采购和删除图书副本（`bookInstances`）。
- 在 User 菜单中访问用户列表及每位用户的详细信息。
- 在 Borrowed 菜单中审批图书借阅请求。

借阅者可以：

- 在 Author 菜单中查看作者。
- 在 Book 菜单中查看图书。
- 在 Book 菜单中申请借阅图书副本（`bookInstance`）。
- 在 Borrowed 菜单中归还图书副本（`bookInstance`）。
- 在 History 菜单中查看历史借阅申请。

== 约束（Constraints）

如果管理员正在审批一条借阅申请，那么允许他们在申请日期之前的日期批准借阅显然是不合理的，应当禁止这种操作。同样，用户归还图书的日期也不应早于审批通过的日期。让我们在 `MyLibraryBorrowed` 中实现这些约束。

.供参考的类图
[plantuml, format="svg", opts="inline"]
----

    PENDING
    APPROVED
    REJECTED
}

class MyLibraryAuthor {
    String firstName
    String lastName
    Date dateOfBirth
    Boolean isActive = true
    String toString()
}

    String title
    String description
    int numberOfPages
    int count = 0
    int getNumberOfInstances()
    int getNumberOfBooksBorrowable()
}

class MyLibraryBookInstance {
    Boolean isActive = true
    Integer serialNumber
    Boolean isAvailableB = true
}

    Date approvalDate
    Date returnDate

}

----

我们需要在领域实体上实现约束，以确保为图书馆提供合规且符合逻辑的数据。

尝试为借阅记录的日期字段添加 `nullable` 约束以及自定义校验器（审批日期不能早于 `requestDate`，且 `returnDate` 不能早于借阅审批日期）。

.参考解答
[%collapsible]
====
.添加以下约束：
[,groovy]
----
static constraints = {
    approvalDate nullable: true, validator: { Date val, MyLibraryBorrowed obj ->
        if (val == null) return true
        return val >= obj.requestDate
    }

    returnDate nullable: true, validator: { Date val, MyLibraryBorrowed obj ->
        if (val == null) return true
        return val >= obj.approvalDate
    }

    bookInstance nullable:false
    user nullable:false
}
----
====
如需了解更多信息，请参阅有关约束的 link:https://docs.grails.org/latest/ref/Constraints/Usage.html[Grails 官方文档]。

== 安全第一部分
太棒了，现在我们已经准备好了所需的一切，只需再添加安全层即可。
Taack 的一大优势就在于实现安全控制非常简单。只需在方法上方添加 `@Secured(['ROLE_ADMIN'])`，即可保护该方法不被任何没有 `ROLE_ADMIN` 角色的用户访问。`@Secured(['ROLE_ADMIN'])` 不仅会隐藏对应图标，还会使该方法无法通过直接链接访问。

让我们继续为相关方法添加 `@Secured(['ROLE_ADMIN'])` 和 `@Secured(['ROLE_BORROWER'])`。[TODO 6.1] 提示：在 `MyLibraryController` 中总共需要添加 11 处 `@Secured` 注解。

在较大型的项目中，通过添加条件语句来隐藏按钮或列可能会变得非常复杂。因此，我们建议对于使用同一个构建器（builder）的所有页面或模态框，尽量保持相同的显示列数/行数。在这种情况下，如果需要隐藏按钮，可以使用另一种技术。

.SecurityService

private static boolean approvedSecurityClosure(Long id, Map p) {
    MyLibraryBorrowed borrowed = MyLibraryBorrowed.get(id)
    return (borrowed.statusOfApproval != ApprovalStatus.APPROVED)
}
