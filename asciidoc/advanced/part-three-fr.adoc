== Introduction

Dans cette section, nous allons découvrir la sécurité et les contraintes. Tout d'abord, nous apprendrons à implémenter ces contraintes, ce qui nous permettra de restreindre les saisies des utilisateurs. Ensuite, nous aborderons la sécurité en créant deux types d'utilisateurs : les administrateurs et les emprunteurs, chacun ayant accès à des fonctionnalités différentes.

Les administrateurs pourront :

- ajouter, supprimer et réactiver des auteurs dans le menu Author.
- ajouter des livres dans le menu Book.
- acheter et supprimer des exemplaires (`bookInstances`) dans le menu Book.
- avoir accès à la liste des utilisateurs et aux informations concernant chacun d'eux dans un menu User.
- approuver des livres dans le menu Borrowed.

Les emprunteurs pourront :

- voir les auteurs dans le menu Author.
- voir les livres dans le menu Book.
- demander un exemplaire (`bookInstance`) dans le menu Book.
- rendre un exemplaire (`bookInstance`) dans le menu Borrowed.
- consulter leurs demandes passées dans le menu History.

== Contraintes

Si un administrateur approuve une demande, il ne serait pas logique qu'il puisse approuver le livre à une date antérieure à celle de la demande ; il ne devrait pas être autorisé à le faire. Il en va de même pour la date à laquelle l'utilisateur rend le livre : il ne devrait pas pouvoir le rendre avant la date d'approbation. Implémentons cela dans `MyLibraryBorrowed`.

Nous devons implémenter des contraintes sur nos entités de domaine afin de nous assurer de fournir des données conformes et logiques à notre bibliothèque.

Essayez d'ajouter une contrainte `nullable` sur les dates d'emprunt, accompagnée d'un validateur (la date d'approbation doit être postérieure ou égale à `requestDate`, et `returnDate` doit être postérieure ou égale à la date d'approbation de l'emprunt).

.Solution
[%collapsible]
====
.Ajoutez les contraintes suivantes :
[,groovy]
----
static constraints = {
    approvalDate nullable: true, validator: { Date val, MyLibraryBorrowed obj ->
        if (val == null) return true
        return val >= obj.requestDate
    }

    returnDate nullable: true, validator: { Date val, MyLibraryBorrowed obj ->
        if (val == null) return true
        return val >= obj.approvalDate
    }

    bookInstance nullable:false
    user nullable:false
}
----
====
Pour plus d'informations, consultez la link:https://docs.grails.org/latest/ref/Constraints/Usage.html[documentation Grails] sur les contraintes.

== Menu Utilisateur (User Menu)
Comme expliqué précédemment, nous souhaitons également disposer d'une table affichant tous les utilisateurs pour les administrateurs.

[,groovy]

UiTableSpecifier buildUsersTable() {
    UiTableSpecifier buildUsersSpecifier = new UiTableSpecifier()
    User user = new User()

    buildUsersSpecifier.ui {
        header {
            label user.username_
            label "Authorities"
        }

        TaackFilter taackFilter = taackFilterService.getBuilder(User)
                .setSortOrder(TaackFilter.Order.ASC, user.username_)
                .setMaxNumberOfLine(10).build()

        iterate taackFilter, {User userIterator ->
            rowColumn {
                rowAction ActionIcon.SHOW * IconStyle.SCALE_DOWN, MyLibraryController.&showUser as MC, userIterator.id
                rowField userIterator.username_
            }
            rowField userIterator.authorities_
        }
    }
}

== Sécurité Partie 1
Parfait, nous avons maintenant tout ce qu'il nous faut. Il ne nous reste plus qu'à ajouter la couche de sécurité.
L'un des grands atouts de Taack est la simplicité de cette opération. En ajoutant simplement `@Secured(['ROLE_ADMIN'])` au-dessus d'une méthode, vous protégez cette méthode contre tout utilisateur ne possédant pas le rôle `ROLE_ADMIN`. `@Secured(['ROLE_ADMIN'])` va non seulement masquer l'icône, mais aussi rendre la méthode inaccessible via un lien direct.

Ajoutons donc `@Secured(['ROLE_ADMIN'])` et `@Secured(['ROLE_BORROWER'])` aux méthodes nécessaires. [TODO 6.1] Indice : il y a un total de 11 annotations `@Secured` à ajouter dans `MyLibraryController`.

Dans des projets plus vastes, l'ajout d'instructions conditionnelles pour masquer des boutons ou des colonnes peut devenir très complexe. C'est pourquoi nous recommandons d'essayer de conserver le même nombre de colonnes/lignes affichées pour toutes les pages et fenêtres modales utilisant le même builder. Pour masquer des boutons dans ce cas, vous pouvez utiliser une autre technique.

== Sécurité Partie 2
Vous pouvez créer un fichier dans lequel vous spécifierez les méthodes qui doivent être sécurisées ainsi que les conditions dans lesquelles certaines méthodes doivent l'être.

Rendez-vous dans `intranet/app/myLibrary/grails-app/services/my/library/MyLibrarySecurityService.groovy` qui a été créé pour vous.

La plupart des méthodes ont déjà été implémentées pour vous. Lisez la documentation dans le fichier pour plus d'informations.

En reprenant la même idée que `returnSecurityClosure` (qui vérifie si `ApprovalStatus` est `APPROVED` pour autoriser l'utilisateur à voir le bouton permettant de rendre un livre), vous allez implémenter `approvedSecurityClosure`.

Mode Pro : implémentez `approvedSecurityClosure` [TODO 6.2]


.SecurityService
[%collapsible]
====
[,groovy]
----
private static boolean approvedSecurityClosure(Long id, Map p) {
    MyLibraryBorrowed borrowed = MyLibraryBorrowed.get(id)
    return (borrowed.statusOfApproval != ApprovalStatus.APPROVED)
}
----
====
