== Qu'est-ce que c'est ?

JDBC signifie *Java Database Connectivity*. C'est un composant Java ancien, important et extrêmement utilisé. Il simplifie l'interrogation et l'édition de données entre différents programmes.

Notre implémentation JDBC actuelle permet uniquement d'interroger les données depuis l'Intranet.

La mise à jour des données par ce biais est un sujet complexe. Nous devons gérer les droits des utilisateurs et la validation des données qui ne sont pas décrits au niveau de la base de données, mais directement dans le code de l'Intranet. Une nouvelle approche est nécessaire de notre côté pour éviter de dupliquer le code.

== Où interroger les données avec ce pilote ?

Seuls *3 logiciels* ont été testés avec ce pilote jusqu'à présent :
|===
|Programme          |Introspection ?|Requêtage ?|Mise à jour ? | Insertion ?

|LibreOffice 7.3    |Liste des tables uniquement|Oui|Non       | Non
|dBeaver            |Oui            |Oui        |Pas encore    | Pas encore
|Intellij           |Oui            |Oui        |Pas encore    | Pas encore
|===

L'#introspection# vous aide lors de l'écriture de requêtes grâce à l'*autocomplétion*. Pendant la saisie de la requête, le programme vous indiquera les tables et les champs disponibles.

Il existe 2 méthodes de travail pour analyser les données :

* Écrire et tester la requête dans un logiciel prenant en charge l'*introspection* ;
* Puis, soit :
** Utiliser la requête saisie directement dans *LibreOffice*
** Ou travailler avec une *extraction CSV* et l'importer dans n'importe quel logiciel (y compris *Office*)

== Requêtes TQL

La principale différence entre un pilote JDBC classique et le nôtre est le langage de requête.

Nous avons développé le *TQL* (Taack Query Language), dont voici quelques avantages :

* Sécurisé, nous vérifions la requête saisie avant de l'envoyer à la base de données réelle
* Syntaxe simple :
** Moins besoin de jointures
** Accès aux champs référencés (voir <<easy-syntax>> point (2))
* Indépendant de la base de données

=== Structure des requêtes de base

[source,sql]
[[easy-syntax]]
.Exemple de base TQL
----
select                              <1>
    l.client.firstName,             <2>
    l.rep.username                  <2>
from Lead l                         <3>
where l.dateCreated > '2022-01-01'  <4>
----
<1> #Clause Select#, permettant de sélectionner des *colonnes* ;
<2> #Champs déréférencés#, si la colonne est elle-même un objet, vous pouvez accéder récursivement aux champs de l'objet. Ici, `rep` est un objet `User` qui contient lui-même des champs (comme `username`) ;
<3> #Clause From#, permettant de choisir des *tables*, ici nous utilisons un _alias_ `l`
<4> #Clause Where# permettant de filtrer les données.

=== Requêtes de base avec formules

Il est possible d'ajouter des formules arithmétiques dans la clause select.

[source,sql]
[[basic-query-with-formulas]]
.Exemple de base TQL avec formules
----
select
    ll.lead.name,
    ll.qty * ll.salePrice as totalWoTaxes   <1>
from LeadLine ll
where ll.qty * ll.salePrice > 100           <2>
----
<1> La #clause Select# prend en charge à la fois les `alias de colonne` et les opérations arithmétiques
<2> La #clause Where# prend également en charge l'arithmétique

WARNING: Le nom de l'alias de colonne doit commencer par une lettre minuscule et faire uniquement partie du jeu de caractères ASCII7.

=== Requêtes avec regroupement

La clause de regroupement ajoute la possibilité d'agréger des données.
L'exemple <<basic-query-with-formulas>> ne comporte pas une ligne par offre, mais par ligne d'offre.
Il est possible d'utiliser le regroupement pour obtenir une ligne par offre, comme dans l'exemple suivant :

[source,sql]
.Exemple TQL avec regroupement et formules
----
select
    ll.lead.rep.mainSubsidiary as salesmanSubsidiary,   <1>
    count(ll.id),                                       <2>
    sum(ll.qty * ll.salePrice)                          <2>
from LeadLine ll
group by ll.lead.rep.mainSubsidiary                     <1>
----
<1> Champ standard, il doit figurer dans la #clause Group by# ;
<2> Vous pouvez utiliser les fonctions d'agrégation #count# ou #sum#.

WARNING: Les alias de colonnes ne sont pas pris en charge sur les colonnes agrégées

=== Requêtes avec jointures internes (Inner Joins)

Parfois, une colonne pointe vers plusieurs lignes.

On appelle cela une relation *plusieurs-à-plusieurs* (many-to-many). Nous ne pouvons pas utiliser directement les champs référencés, vous devez utiliser ce qu'on appelle des *jointures* (joins) ... (cela fait très années 70, mais ce n'est pas de ma faute)

Dans l'exemple suivant, les *Items* contiennent plusieurs *Values*, et les *Values* peuvent être utilisées par plusieurs *Items*. Si nous voulons lister les Items et les Values dans la même table, nous avons besoin d'une sorte de produit cartésien entre 2 ensembles de données.

WARNING: La cardinalité du produit cartésien de 2 ensembles est #M x N#, vous devez utiliser la *clause Where* pour réduire le nombre de résultats.

[source,sql]
.Jointure simple TQL
----
select
    i.name,
    i.ref,
    v.valueString,
    v.associatedProperty.valueKind as kind,
    v.associatedProperty.kindOfCharacteristic as typeOfChar,
    v.associatedProperty.nameAlias as nameAlias
from Item i, Value v                                    <1>
where v in elements(i.values) and i.range.name = 'DVM'  <2>

----
<1> Nous listons 2 tables indépendamment
<2> Nous *DEVONS* limiter le nombre de résultats avec l'expression `v in elements(i.values)`

== Limitations actuelles du pilote

* Vous ne pourrez pas *déréférencer* les champs de langue (`v.valueMap['fr']` échouera, tout comme `v.valueMap`).
* Nous prenons uniquement en charge les jointures internes (Inner join), et non les jointures externes (outer join). Notre implémentation actuelle des jointures est lente ; nous pouvons l'améliorer, mais c'est plus complexe.
