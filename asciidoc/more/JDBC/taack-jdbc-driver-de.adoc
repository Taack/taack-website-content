== Was ist das?

JDBC steht für *Java Database Connectivity*. Es ist eine alte, wichtige und äußerst weit verbreitete Java-Komponente. Sie vereinfacht das Abfragen und Bearbeiten von Daten zwischen verschiedenen Programmen.

Unsere aktuelle JDBC-Implementierung erlaubt lediglich das Abfragen von Daten aus dem Intranet.

Das Aktualisieren von Daten auf diesem Weg ist ein komplexes Thema. Wir müssen Benutzerrechte und Datenvalidierungen berücksichtigen, die nicht auf Datenbankebene, sondern direkt im Code des Intranets beschrieben sind. Auf unserer Seite ist ein neuer Ansatz erforderlich, um eine Duplizierung des Codes zu vermeiden.

== Wo können Daten mit diesem Treiber abgefragt werden?

Bisher wurden nur *3 Softwareprogramme* mit diesem Treiber getestet:
|===
|Programm           |Introspektion? |Abfragen?  |Aktualisieren? | Einfügen?

|LibreOffice 7.3    |Nur Tabellenliste|Ja       |Nein           | Nein
|dBeaver            |Ja             |Ja         |Noch nicht     | Noch nicht
|Intellij           |Ja             |Ja         |Noch nicht     | Noch nicht
|===

#Introspektion# unterstützt Sie beim Schreiben von Abfragen durch die *Autovervollständigung*. Während der Eingabe der Abfrage zeigt Ihnen das Programm die verfügbaren Tabellen und Felder an.

Es gibt 2 Arbeitsmuster, um Daten zu analysieren:

* Schreiben und testen Sie die Abfrage in einer Software, die *Introspektion* unterstützt;
* Danach entweder:
** Verwenden Sie die eingegebene Abfrage direkt in *LibreOffice*
** Oder arbeiten Sie mit einem *CSV-Export* und importieren Sie diesen in eine beliebige Software (einschließlich *Office*)

WARNING: Ich werde später Videos dazu erstellen, wie man den Treiber mit diesen Programmen einrichtet.

[[_tql_queries]]
== TQL-Abfragen

Der Hauptunterschied zwischen einem regulären JDBC-Treiber und unserem liegt in der Abfragesprache.

Wir haben *TQL* (Taack Query Language) entwickelt; hier sind einige Vorteile:

* Abgesichert: Wir prüfen die eingegebene Abfrage, bevor wir sie an die eigentliche Datenbank senden
* Einfache Syntax:
** Weniger Bedarf an Joins
** Zugriff auf referenzierte Felder (siehe <<easy-syntax>> Punkt (2))
* Datenbankunabhängig

=== Aufbau einfacher Abfragen

[source,sql]
[[easy-syntax]]
.Einfaches TQL-Beispiel
----
select                              <1>
    l.client.firstName,             <2>
    l.rep.username                  <2>
from Lead l                         <3>
where l.dateCreated > '2022-01-01'  <4>
----
<1> #Select-Klausel#, ermöglicht die Auswahl von *Spalten*;
<2> #Dereferenzierte Felder#: Wenn die Spalte selbst ein Objekt ist, können Sie rekursiv auf Objektfelder zugreifen. Hier ist `rep` ein `User`-Objekt, das wiederum eigene Felder enthält (wie `username`);
<3> #From-Klausel#, ermöglicht die Auswahl von *Tabellen*, hier verwenden wir einen _Alias_ `l`
<4> #Where-Klausel#, ermöglicht das Filtern von Daten.

=== Einfache Abfragen mit Formeln

Es ist möglich, arithmetische Formeln in der Select-Klausel hinzuzufügen.

[source,sql]
[[basic-query-with-formulas]]
.Einfaches TQL-Beispiel mit Formeln
----
select
    ll.lead.name,
    ll.qty * ll.salePrice as totalWoTaxes   <1>
from LeadLine ll
where ll.qty * ll.salePrice > 100           <2>
----
<1> #Select-Klausel#, unterstützt sowohl `Spalten-Aliase` als auch arithmetische Operationen
<2> #Where-Klausel# unterstützt ebenfalls Arithmetik

WARNING: Der Name eines Spalten-Alias muss mit einem Kleinbuchstaben beginnen und darf nur Zeichen aus dem ASCII7-Zeichensatz enthalten.

=== Abfragen mit Gruppierung

Die Gruppierungsklausel bietet die Möglichkeit, Daten zu aggregieren.
Das <<basic-query-with-formulas>> liefert nicht eine Zeile pro Angebot, sondern pro Angebotsposition.
Mithilfe einer Gruppierung lässt sich eine Zeile pro Angebot erhalten, wie im folgenden Beispiel:

[source,sql]
.TQL-Beispiel mit Gruppierung und Formeln
----
select
    ll.lead.rep.mainSubsidiary as salesmanSubsidiary,   <1>
    count(ll.id),                                       <2>
    sum(ll.qty * ll.salePrice)                          <2>
from LeadLine ll
group by ll.lead.rep.mainSubsidiary                     <1>
----
<1> Standardfeld, muss in der #Group-by-Klausel# aufgeführt werden;
<2> Sie können die Aggregationsfunktionen #count# oder #sum# verwenden.

WARNING: Spalten-Aliase werden für aggregierte Spalten nicht unterstützt

=== Abfragen mit Inner Joins

Manchmal verweist eine Spalte auf mehr als eine Zeile.

Dies wird als *Many-to-Many*-Beziehung (viele-zu-viele) bezeichnet. Wir können referenzierte Felder hier nicht direkt verwenden, sondern müssen sogenannte *Joins* einsetzen ... (das klingt nach den 70er-Jahren, liegt aber nicht an mir).

Im nächsten Beispiel enthalten *Items* viele *Values*, und *Values* können von mehr als einem *Item* verwendet werden. Wenn wir Items und Values in derselben Tabelle auflisten möchten, benötigen wir eine Art Kreuzprodukt zwischen 2 Datenmengen.

WARNING: Die Kardinalität des Kreuzprodukts zweier Mengen beträgt #M x N#. Sie müssen eine *Where-Klausel* verwenden, um die Anzahl der Ergebnisse zu reduzieren.

[source,sql]
.Einfacher TQL-Join
----
select
    i.name,
    i.ref,
    v.valueString,
    v.associatedProperty.valueKind as kind,
    v.associatedProperty.kindOfCharacteristic as typeOfChar,
    v.associatedProperty.nameAlias as nameAlias
from Item i, Value v                                    <1>
where v in elements(i.values) and i.range.name = 'DVM'  <2>

----
<1> Wir führen 2 Tabellen unabhängig voneinander auf
<2> Wir *MÜSSEN* die Anzahl der Ergebnisse mit dem Ausdruck `v in elements(i.values)` begrenzen

== Aktuelle Einschränkungen des Treibers

* Sie können Sprachfelder nicht *dereferenzieren* (`v.valueMap['fr']` schlägt fehl, ebenso `v.valueMap`).
* Wir unterstützen nur Inner Joins, keine Outer Joins. Unsere aktuelle Join-Implementierung ist langsam; wir können das verbessern, aber es ist komplexer.
