[[filterFieldExpressionReverse]]
.Nuovo filtro filterFieldExpressionReverse
====
.Filtro filterFieldExpressionReverse
[source,groovy]
----
def parentParts() {
    UiFilterSpecifier f = new UiFilterSpecifier().sec PlmFreeCadPart, {         <1>
        PlmFreeCadLink link = new PlmFreeCadLink()
        filterFieldExpressionReverse(link.part_,                                <2>
                true,                                                           <3>
                new FilterExpression(null as Object, Operator.NE, link.part_))  <4>
    }
    taackUiService.show(new UiBlockSpecifier().ui {
        tableFilter(plmFreeCadUiService.buildPartFilter(), plmFreeCadUiService.buildPartTable(null, f), {
            menuIcon ActionIcon.GRAPH, this.&model as MC
        })
    }, buildMenu())
}
----
<1> Stiamo costruendo un filtro per `PlmFreeCadPart`
<2> Vogliamo elencare gli assiemi padre, ovvero quelli per cui il campo `PlmFreeCadLink part` non punta al `PlmFreeCadPart` elencato
<3> `true` sta per `notIn`
<4> Letteralmente: vogliamo tutti i *PlmFreeCadPart* che non sono figli

.HQL generato
[source,hql]
----
select
    distinct sc  ,sc.dateCreated
from PlmFreeCadPart sc
where
    sc.id NOT IN (select auo.part.id from PlmFreeCadLink auo where auo.part IS NOT NULL)    <1>
    and sc.nextVersion IS NULL
order by sc.dateCreated DESC
----

<1> Clausola `where` aggiunta dall'espressione `filterFieldExpressionReverse`

[[show-grid-layout]]
.Layout a griglia per Show (Show Grid Layout)
====

.Disporre uno Show su una griglia responsiva tramite `ShowLayout.GRID`
[source,groovy]
----
new UiShowSpecifier().ui ShowLayout.GRID, {                      <1>
    fieldLabeled item.ref_
    fieldLabeled item.name_
    fieldLabeled item.itemStatus_
    fieldLabeled item.gtin_
    fieldLabeled Style.SPAN_TWO, item.labeling_                  <2>
    fieldLabeled Style.BOLD + Style.SPAN_FULL, item.description_ <3>
}
----

<1> Passare `ShowLayout.GRID` per disporre i campi su una griglia ad adattamento automatico invece che verticalmente in una colonna. Il valore predefinito è `ShowLayout.LIST`.
<2> Ogni campo occupa per impostazione predefinita una cella della griglia. `Style.SPAN_TWO` / `Style.SPAN_THREE` possono essere utilizzati per far sì che le celle si estendano su più colonne.
<3> `Style.SPAN_FULL` fa sì che un campo occupi l'intera riga. Gli span si combinano con qualsiasi altro stile tramite `+` (qui con `Style.BOLD`).

Si noti che la griglia adatta automaticamente tante colonne quante ne consente la larghezza del contenitore, ciascuna larga almeno `220px` (`grid-template-columns: repeat(auto-fit, minmax(220px, 1fr))` sulla classe `taackShowGrid`; il valore minimo può essere sovrascritto nel proprio CSS).

== Versione 0.7.0

* Grails 7, Gradle 8.4, Java 24, Groovy 4.0.28 ...
* Miglioramento delle prestazioni: avvio anticipato della trasmissione della pagina e minore consumo di memoria per pagina
* Suddivisione di `taack-ui` in `taack-ui`, `taack-ui-jdbc`, `taack-ui-pdf`, `taack-ui-ssh`, `taack-ui-search`, `taack-ui-asciidoc`. Un server minimale che utilizza solo `taack-ui` dovrebbe produrre un Jar di circa 70 MB
* Menu contestuali per campi e classi (vedere <<contextual-menu-code-sample>>)
* Helper di notifica: consente di contrassegnare le righe non lette in una tabella tramite il setter del filtro `setLastReadingDate` (vedere <<notification-setLastReadingDate-sample>>)
* #Modifiche a SolrSearch#: il contesto degli oggetti deve essere registrato in modo generico (vedere <<TaackGormClassRegisterService>>)
* Nuova personalizzazione dei diagrammi tramite builder, facilitando l'integrazione dei diagrammi nelle e-mail e nei PDF (vedere <<diagram-builders>>)
* Editor Asciidoc con funzionalità di conversione su copia/incolla (vedere <<asciidoc-editor>>)
* Miglioramento dell'output dei diagrammi nelle e-mail e nei PDF
* `TaackUiConfiguration` non viene più inizializzato tramite `application.yml`; i membri sono statici e possono essere modificati in `server/grails-app/init/.../Application.groovy` (vedere <<taack-ui-configuration>>)
* È ora possibile ricevere una callback su un evento di rilascio (drop) su una tabella o una cella di tabella (vedere <<drop-on-table>>, <<drop-on-cell>>)

[[new_solr_code]]
.Nuova semplificazione del DSL Solr (non è più necessaria l'etichettatura)
[source,groovy]
----
@PostConstruct
private void init() {
    taackSearchService.registerSolrSpecifier(this,
            new SolrSpecifier(User,
                CrewController.&showUserFromSearch as MethodClosure,
                this.&labeling as MethodClosure, { User u ->
        u ?= new User()
        indexField SolrFieldType.TXT_NO_ACCENT, u.username_
        indexField SolrFieldType.TXT_GENERAL, u.username_
        indexField SolrFieldType.TXT_NO_ACCENT, u.firstName_
        indexField SolrFieldType.TXT_NO_ACCENT, u.lastName_
        indexField SolrFieldType.POINT_STRING, "mainSubsidiary", true, u.subsidiary?.toString()
        indexField SolrFieldType.POINT_STRING, "businessUnit", true, u.businessUnit?.toString()
        indexField SolrFieldType.DATE, 0.5f, true, u.dateCreated_
        indexField SolrFieldType.POINT_STRING, "userCreated", 0.5f, true, u.userCreated?.username
    }))
}
----

== Versione 0.4.0

* Niente più `paginate` nelle tabelle. Vedere <<new_iterate_code>>
* Niente `list`, ma un `iterate` che accetta una closure come parametro, con un approccio basato sul pattern builder per passare gli argomenti
* I menu vengono ora etichettati automaticamente (usare `lang=test` nell'URL per tradurre i menu). Vedere <<new_menu_code>>
* Niente più parametro #isAjax# nelle tabelle ... Vedere <<new_rowAction_code>>
* Sostituzione di `rowLink` con `rowAction` <<i18n_isAjax>>
* Nessuna etichetta necessaria su #rowAction# nelle tabelle. Vedere <<new_rowAction_code>>
* Non è più richiesto `ajaxBlock` per tabelle, moduli e `tableFilters`
* `formAction` non ha più il parametro #isAjax#
* `formAction` non ha più il parametro i18n obbligatorio
* `form` non ha più il parametro i18n obbligatorio, l'i18n si basa sul nome dell'azione corrente
* L'azione di blocco non ha più il parametro i18n obbligatorio, l'i18n si basa sull'azione di destinazione
* L'azione di blocco non ha più il parametro `isAjax` obbligatorio
